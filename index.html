Theory / Study

Study of Basic Elements of Computer Networking and Networking Devices

AIM: To study the basic elements of computer networking and networking devices.

ℹ️ Practical 1 is mainly a study/theory practical — no major configuration is required in Packet Tracer.

🔌Basic Network Elements

  • Sender – Originates and transmits data
  • Receiver – Accepts and processes data
  • Transmission Medium – Copper cable, fibre, or wireless
  • NIC – Network Interface Card, connects device to the network
  • Protocol – Set of rules governing communication (TCP/IP, HTTP, etc.)
  • IP Address – Logical address for routing (e.g. 192.168.1.1)
  • MAC Address – Physical hardware address (e.g. AA:BB:CC:DD:EE:FF)

🖧Common Networking Devices

DeviceFunction
HubSends data to all ports (broadcasts)
SwitchForwards frames to the correct port
RouterConnects different networks via IP routing
ModemConverts digital ↔ analog signals (ISP link)
Access PointProvides wireless (Wi-Fi) connectivity
RepeaterRegenerates / extends a signal
BridgeConnects two LAN segments at data-link layer

💡Packet Tracer Identification Steps

  1. Open Cisco Packet Tracer.
  2. From the device panel, identify: PC, Laptop, Server, Hub, Switch, Router, Wireless devices.
  3. From the Connections section, identify cable types: Straight-Through, Crossover, Serial DCE, Fibre.
  4. Hover over each device icon to read its description and function.
  5. Note that router interfaces are OFF by default — always use no shutdown.

🔑 Key Points

Hub= sends data to all ports (Layer 1)
Switch= forwards frames to the appropriate port (Layer 2)
Router= connects different networks (Layer 3)
Access Point= provides wireless connectivity
Repeater= regenerates / extends a signal
✅ Result: Basic networking elements and networking devices were studied.

Sliding Window Protocol – Go-Back-N and Selective Repeat

AIM: To study and simulate Go-Back-N and Selective Repeat sliding window ARQ protocols.

ℹ️ This practical is implemented using a programming/simulation environment rather than standard Packet Tracer.

📤Go-Back-N – Concept

Sender transmits multiple frames within a window size. If one frame is lost or erroneous, the sender retransmits that frame and all frames that follow it.

📝Implementation Plan

  1. Define total number of frames, window size, and which frame will be lost/errored.
  2. Sender transmits frames within the window.
  3. Simulate the error/lost frame at the specified position.
  4. Receiver detects missing frame via sequence number gap.
  5. Sender retransmits the missing frame and all subsequent frames.
  6. Display ACK numbers and retransmission events on screen.
  7. Continue until all frames are acknowledged.

📤Selective Repeat – Concept

Receiver buffers correctly-received out-of-order frames. Sender retransmits only the lost or errored frame.

📝Implementation Plan

  1. Define window size, total frames, and error frame.
  2. Sender transmits frames within the window.
  3. Simulate loss of one specific frame.
  4. Receiver stores correctly-received out-of-order frames in a buffer.
  5. Receiver sends ACKs for every correctly received frame.
  6. Sender retransmits only the missing frame.
  7. Receiver delivers all frames in order after gap is filled.
  8. Display buffer state, ACKs, and retransmissions.

Packet Analysis

HTTP, TCP and ICMP using Wireshark

AIM: To capture and analyze HTTP, TCP and ICMP packets using Wireshark.

⚠️ Wireshark must be installed on the computer and the correct network interface must be selected before starting a capture.

📡ICMP Steps

  1. Open Wireshark.
  2. Select the active network interface (e.g. Ethernet, Wi-Fi).
  3. Click Start capture (blue shark-fin button).
  4. Open Command Prompt.
  5. Run ping command (see below).
  6. Stop the capture (red square button).
  7. Apply the display filter: icmp
  8. Observe Echo Request and Echo Reply packets.
  9. Inspect source and destination IP addresses.

🔍ICMP Packet Fields

Type 8Echo Request (sent by pinging host)
Type 0Echo Reply (sent by target host)
Source IPYour machine's IP address
Dest IPTarget IP (e.g. 8.8.8.8)
TTLTime To Live – decremented per hop
Command Prompt
ping 8.8.8.8
(If no Internet: ping another device on your LAN)

📋TCP Steps

  1. Start a new Wireshark capture.
  2. Visit a website or generate TCP traffic.
  3. Stop the capture.
  4. Apply filter: tcp
  5. Find packets with flags: SYN, SYN-ACK, ACK.
  6. Right-click a packet → Follow → TCP Stream for full session.
Wireshark Filter – TCP
tcp
tcp.flags.syn == 1
tcp.flags.ack == 1 && tcp.flags.syn == 1

🌐HTTP Steps

  1. Start a Wireshark capture.
  2. Visit an HTTP (not HTTPS) website, or use a lab HTTP server.
  3. Stop the capture.
  4. Apply filter: http
  5. Inspect HTTP Request and HTTP Response packets.
⚠️ Most modern websites use HTTPS (TLS-encrypted), so the http filter may show nothing. Use a plain HTTP lab server or type http:// explicitly.
